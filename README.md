# injectable — DI Playground

An interactive Flutter showcase for the [`injectable`](https://pub.dev/packages/injectable) package — a code generator for [`get_it`](https://pub.dev/packages/get_it) that brings annotation-driven dependency injection to Dart.

Each feature is a standalone, runnable demo. Read the concept, see the annotation, watch it work live.

---

## Features Covered

| Annotation | Concept | What the demo shows |
|---|---|---|
| `@injectable` | Factory | Every `getIt<T>()` call creates a fresh instance with its own state |
| `@singleton` | Eager Singleton | One instance, shared forever — re-fetching returns the same object |
| `@lazySingleton` | Lazy Singleton | Created only on first access — tracks initialization time |
| `@Named()` | Named Registrations | Multiple `Logger` implementations switched by name at runtime |
| `@dev` / `@prod` | Environment Scoping | `DevApiClient` vs `ProdApiClient` — same interface, different impl per env |
| `@module` | Modules | Register `HttpService` (a "third-party" class) without modifying its source |
| `@factoryMethod` (async) | Async Init | `DatabaseService` opens asynchronously — connect then query |

## How injectable Works

Injectable is a **code generator** — you annotate your classes, run `build_runner`, and get a `GetIt`-compatible registration function automatically.

### 1. Annotate your classes

```dart
// Factory: new instance on every call
@injectable
class CounterService { ... }

// Singleton: one instance, app lifetime
@singleton
class AppStateService { ... }

// Lazy singleton: created on first access
@lazySingleton
class AnalyticsService { ... }

// Named: multiple implementations of one interface
@Named('console')
@Injectable(as: Logger)
class ConsoleLogger implements Logger { ... }

// Environment-scoped
@dev
@Injectable(as: ApiClient)
class DevApiClient implements ApiClient { ... }

// Third-party classes via module
@module
class AppModule {
  @singleton
  HttpService get httpService => const HttpService(baseUrl: '...');
}

// Async factory method
@lazySingleton
class DatabaseService {
  @factoryMethod
  static Future<DatabaseService> init() async { ... }
}
```

### 2. Set up injection.dart

```dart
import 'package:get_it/get_it.dart';
import 'package:injectable/injectable.dart';
import 'injection.config.dart';

final getIt = GetIt.instance;

@InjectableInit(asExtension: true)
Future<GetIt> configureDependencies({String env = Environment.dev}) async =>
    getIt.init(environment: env);
```

### 3. Initialize in main.dart

```dart
void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await configureDependencies(env: Environment.dev); // or Environment.prod
  runApp(const App());
}
```

### 4. Generate

```bash
dart run build_runner build --delete-conflicting-outputs
```

This produces `injection.config.dart` — never edit it by hand.

### 5. Use

```dart
// Direct access:
final counter = getIt<CounterService>();

// Named:
final logger = getIt<Logger>(instanceName: 'console');

// Async lazy singleton:
final db = await getIt.getAsync<DatabaseService>();
```

## What Gets Generated

```dart
// injection.config.dart (generated — do not edit)
extension GetItInjectableX on GetIt {
  GetIt init({String? environment, EnvironmentFilter? environmentFilter}) {
    final gh = GetItHelper(this, environment, environmentFilter);
    final appModule = AppModule();

    gh.factory<CounterService>(() => CounterService());
    gh.singleton<AppStateService>(() => AppStateService());
    gh.lazySingleton<AnalyticsService>(() => AnalyticsService());
    gh.factory<Logger>(() => ConsoleLogger(), instanceName: 'console');
    gh.factory<Logger>(() => RemoteLogger(),  instanceName: 'remote');
    gh.factory<ApiClient>(() => DevApiClient(),  registerFor: {Environment.dev});
    gh.factory<ApiClient>(() => ProdApiClient(), registerFor: {Environment.prod});
    gh.singleton<HttpService>(() => appModule.httpService);
    gh.lazySingletonAsync<DatabaseService>(() => DatabaseService.init());

    return this;
  }
}
```

## Key Concepts

### Factory vs Singleton vs Lazy Singleton

| | Factory | Singleton | Lazy Singleton |
|---|---|---|---|
| When created | Every call | App startup | First access |
| Instance count | N (one per call) | 1 | 1 |
| State sharing | ❌ None | ✅ Shared | ✅ Shared |
| Startup cost | None | Full | Deferred |
| Use for | Stateful, short-lived | App config, auth, cache | Heavy services |

### Named Registrations

Named registrations solve the "which implementation?" problem without conditional logic scattered through your code:

```dart
// Bad: manual if-else everywhere
Logger logger = isDebug ? ConsoleLogger() : RemoteLogger();

// Good: injectable resolves it by name, caller stays clean
class ReportService {
  ReportService(@Named('console') this.logger);
}
```

### Environment Scoping

```dart
await configureDependencies(env: Environment.dev);
// → DevApiClient registered for ApiClient

await configureDependencies(env: Environment.prod);
// → ProdApiClient registered for ApiClient
```

Switch your environment at the entry point — no branching in business logic.

### Modules for Third-Party Code

The `@module` pattern lets you bring any class into the DI container, even if you can't annotate it (packages, platform types, etc.):

```dart
@module
class AppModule {
  @singleton
  Dio get dio => Dio(BaseOptions(baseUrl: 'https://api.example.com'));

  @lazySingleton
  Future<SharedPreferences> get prefs => SharedPreferences.getInstance();
}
```

## Relation to Other DI Frameworks

injectable is inspired by Angular DI, Dagger (Android), and Guice. If you've used any of these, the mental model transfers directly:

| Concept | Angular | Dagger | injectable |
|---|---|---|---|
| Factory | `useFactory` | `@Provides` | `@injectable` |
| Singleton | `providedIn: 'root'` | `@Singleton` | `@singleton` |
| Named | `@Inject(TOKEN)` | `@Named` | `@Named()` |
| Module | `@NgModule` | `@Module` | `@module` |
| Environment | `environment.ts` | `@Qualifier` | `@dev` / `@prod` |
